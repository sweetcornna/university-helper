DOCS · 晨读版

把它跑起来，然后去睡觉。

这份文档讲怎么在本地跑起 University Helper、怎么配环境变量、怎么用 Docker 部署，以及两个平台的功能怎么用。和仓库里的 docs/ 目录说法不一致时，以 docs/ 为准。

概览

University Helper 是一个自托管的校园课程自动化平台，用 FastAPI 和 React 写成。 它替你完成超星学习通的签到和泛雅课程任务，以及智慧树的课程任务， 任务状态保存在你自己的租户数据库里。

  • 每位用户有一个独立的 PostgreSQL 数据库（tenant_<username>），和其他用户的数据分开存放。
  • 第三方平台的账号密码先用 Fernet 对称加密，再写入数据库。
  • REST API 用 JWT 认证，请求带 Authorization: Bearer 头，令牌默认 30 分钟过期。
  • 容器以非 root 用户运行，根文件系统只读；nginx 负责限速和安全响应头。

另有桌面版「学道」（Windows / macOS / Linux），后端打包在安装包里，在本机运行， 不需要 Docker，也不需要注册或登录。

仓库名为 university-helper；部分源码仍保留历史内部名 easy_learning（容器名、环境变量前缀），正在逐步统一。

快速开始

引导脚本会创建 .env，并安装 Python 和 Node 依赖：

terminal
$ bash scripts/setup.sh        # 创建 .env，安装依赖
$ make start                   # docker-compose 栈（应用 + postgres）
$ make test                    # pytest + vitest

只跑后端

terminal
$ cd backend
$ install -m 600 .env.example .env  # 编辑 SECRET_KEY / CORS_ORIGINS / 数据库凭据
$ python -m venv .venv && source .venv/bin/activate
$ pip install -r requirements.txt -r requirements-dev.txt
$ uvicorn app.main:app --reload --host 0.0.0.0 --port 8000

只跑前端

terminal
$ cd frontend
$ npm install
$ npm run dev          # http://localhost:3000，/api 自动代理到 :8000

数据库

需要 PostgreSQL 15+。database/ 下的 schema 文件会被 docker entrypoint 自动执行；Alembic 迁移位于 backend/alembic/versions/，分为独立的 main_db 和 tenant_db 分支。主库在 backend/ 中用 alembic upgrade main_db@head 应用； 在仓库根目录用 python scripts/migrate_tenants.py 将租户分支 应用到所有现有租户数据库。

服务端启动时如果发现主库缺少 users 表，或者缺少注册要用的 tenant_template 模板库，会在后台自动补建；设 DB_AUTO_BOOTSTRAP=false 可以关掉。

环境变量

常用的键如下，「必填」一栏为「是」的必须配置（完整列表见根目录 .env.example）：

变量必填说明
MAIN_DB_HOST / NAME / USER / PASSWORD是主库连接信息。
SECRET_KEY是JWT 签名密钥，长度 ≥ 16 字符（生产建议 ≥ 32）。
CORS_ORIGINS是JSON 数组，例如 ["http://localhost:3000"]。
CREDENTIAL_ENCRYPTION_KEY生产必填Fernet 密钥（urlsafe-base64）。生产环境缺少它应用会拒绝启动；开发环境可省略。
POSTGRES_PASSWORDDocker 部署必填容器内 Postgres 超级用户密码。
APP_PORT否后端监听端口，默认 8000。
ENV否设为 production 启用生产模式校验。
SHUAKE_COMPAT_SECRET否≥ 32 字符时启用 7 天兼容令牌接口 GET /auth/shuake-token。
DOCS_ENABLED否设为 true 时在 /docs 暴露 Swagger UI。
ALLOWED_HOSTS否额外允许的访问域名或 IP，逗号分隔，比如局域网 IP 或第二个域名。localhost、127.0.0.1 和 CORS_ORIGINS 里的主机始终允许，其他 Host 会收到 400「Invalid host header」。ENV=production 时不能设为 *。
ADMIN_EMAILS否管理员邮箱，逗号分隔。管理员登录后能看到新版本提示；留空时，第一个注册的账号就是管理员。
UPDATE_CHECK_ENABLED否默认 true，每 6 小时查一次 GitHub Releases 有没有新版本。服务器连不上 GitHub 时可以设为 false。
生成 Fernet 密钥
$ python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
不要把填了真实密钥的 .env 提交到仓库。第一次对外部署前，先换掉数据库密码和 JWT 密钥。

Docker 部署

一键部署

在服务器上运行下面这行命令。Linux 上还没装 Docker 时，脚本可以用 get.docker.com 自动安装（带 -y 时不再询问）；macOS 和 WSL2 要先装好 Docker Desktop。 如果当前目录不是仓库，脚本先把对应版本的部署文件下载到 university-helper/ 子目录，然后 生成 .env 和随机密钥，拉取预构建镜像，启动 Postgres、后端和 Web， 再等 /health 通过。

terminal
$ curl -fsSL https://github.com/sweetcornna/university-helper/releases/latest/download/deploy_server.sh | bash -s -- -y --admin-email you@example.com
# 默认只在本机访问：http://localhost:8080
# 有域名：追加 --domain your.domain（切到 ENV=production，并生成 nginx 配置模板）
# 没有域名、用公网 IP 访问：追加 --host 203.0.113.10
# 还会用别的地址打开（局域网 IP、第二个域名）：追加 --allowed-hosts 192.168.1.20,www.example.com

--admin-email 指定管理员邮箱，可以写多个，用逗号隔开；不写时第一个注册的账号是管理员。 对外端口默认是 8080，用 --port 可以换。再次运行脚本是安全的：.env 里已有的密钥和数据库都会保留，这次传入的参数会写进 .env。 Windows（Docker Desktop）用 PowerShell 版脚本 deploy_server.ps1，参数是 -Domain、-HostIp、-AdminEmail、-AllowedHosts、-Yes 等。

从源码部署

这种方式使用 docker-compose.server.yml 和 Dockerfile.server。 栈里没有 nginx 容器，TLS 终止和前端静态文件都由宿主机 nginx 负责。 先准备 Node.js 20（以仓库 .nvmrc 为准）；Dockerfile.server 不构建前端，要先生成 frontend/dist/，再配置 nginx。 完整说明见仓库里的 docs/DEPLOYMENT.md。

terminal
$ git clone https://github.com/sweetcornna/university-helper.git
$ cd university-helper
$ install -m 600 .env.example .env   # 填 SECRET_KEY · POSTGRES_PASSWORD · CREDENTIAL_ENCRYPTION_KEY · CORS_ORIGINS
$ node --version          # Node.js 20.x
$ cd frontend && npm ci && npm run build
$ cd ..                    # 回到仓库根目录
$ docker compose -f docker-compose.server.yml -p university-helper up -d --build

第一次部署按这个顺序检查：

  1. 创建并填好 .env（变量见上一节），不要提交到仓库。
  2. 确认上面的 Node.js 20 构建已经完成，frontend/dist/ 已经生成。
  3. 运行 docker compose … up -d --build 启动服务。
  4. 确认 frontend/dist/ 已生成后，再配置宿主机 nginx：TLS 终止、root frontend/dist;、/api/ 反代到 http://127.0.0.1:8000。
  5. 验证：curl -fsS http://127.0.0.1:8000/health。返回里的 schema 是 ok 时才能正常注册。
小改动可以用 scripts/hotfix_publish.sh 更新单个文件（优先用 SSH key 认证）。它把文件同步到服务器上的仓库检出目录，再重建并替换 Compose 的 app 服务，不会直接写入只读的运行容器。仓库根目录旧的 deploy.* 脚本已归档到 scripts/_legacy/，不要再运行。

功能指南 · 超星学习通

登录

在「超星」页面用手机号和密码登录，登录后就能拉取课程列表，凭据加密保存。

签到

  • 支持普通签到、二维码签到和位置签到。位置签到内置地图搜索，搜到地点就能取得坐标。
  • 「一键全签」会对当前所有进行中的签到逐一提交（POST /chaoxing/sign-all）。

泛雅课程任务

在课程页选好课程后发起任务（POST /course/start，platform: "chaoxing"）。 视频和章节测验按章节顺序自动推进，进度和日志随时可查，任务可以暂停、续跑或停止。

功能指南 · 智慧树

登录

  • 扫码登录：发起 POST /course/zhihuishu/qr-login 后页面会显示二维码，用智慧树 App 扫码确认。
  • 密码登录：手机号加密码（POST /course/zhihuishu/password-login）。

课程任务

选好课程后加入队列（POST /course/zhihuishu/tasks/course）。任务在后台一节节播放视频， 进度、日志、暂停、续跑和停止用的是和超星任务同一套接口。

API 参考

Base URL：http://localhost:8000/api/v1（本地）。所有接口返回 JSON，错误统一为 { "code": "ErrorClassName", "message": "…" }。 除公共路由外，所有接口需要 Authorization: Bearer <jwt>。

设 DOCS_ENABLED=true 后，可以在 /docs 的 Swagger UI 里直接调接口，原始 spec 在 /openapi.json。

认证

方法路径用途
POST/auth/register注册：创建用户并自动建租户库，返回 JWT。用户名需匹配 ^[a-z0-9]+$，且不能用 template、postgres、root 等系统保留名；密码 ≥ 8 位且含大小写与数字。桌面版不需要注册，调用会返回 409。
POST/auth/login邮箱 + 密码登录，返回与注册相同的结构。
GET/auth/shuake-token签发 7 天兼容令牌（需配置 SHUAKE_COMPAT_SECRET）。

超星

方法路径用途
POST/chaoxing/login手机号 + 密码登录，预热客户端缓存。
GET/chaoxing/courses列出当前账号的课程。
POST/chaoxing/sign提交单个进行中的签到。
POST/chaoxing/sign-all提交所有进行中的签到。
GET/chaoxing/location/*地理编码 / 地点搜索 / 逆地理编码（公共路由，供地图选点）。

课程任务（超星泛雅 + 智慧树）

方法路径用途
POST/course/start启动课程任务，platform 取 "chaoxing" 或 "zhihuishu"。
GET/course/status/{task_id}轮询任务进度。
GET/course/tasks列出当前用户的任务。
GET/course/logs/{task_id}读取任务日志行。
POST/course/task/{task_id}/pause · /resume · /stop暂停 / 续跑 / 停止任务。
POST/course/zhihuishu/qr-login发起智慧树扫码登录，返回会话 id 与二维码 PNG。
POST/course/zhihuishu/password-login智慧树手机号 + 密码登录。
POST/course/zhihuishu/tasks/course入队智慧树课程任务。

系统

方法路径用途
GET/system/update管理员查询新版本：当前版本、最新版本、更新说明和更新命令。非管理员返回 403；桌面版没有这个接口。
GET/health（不带 /api/v1 前缀）健康检查，公共路由。服务端版的 schema 字段为 ok 表示可以注册；missing_users、missing_tenant_template 表示数据库还没准备好。

轮询 status 与 logs 时请带退避间隔；任务数据以 JSONB 存于你的租户库（course_task_store）。

常见问题

注册时提示用户名或密码不合法？

用户名只允许小写字母与数字（^[a-z0-9]+$），template、postgres、root、system 等系统保留名不能用；密码至少 8 位，且必须同时包含大写字母、小写字母和数字。

注册时提示「服务器出错了」或数据库还没初始化好？

先在服务器上运行 curl -fsS http://127.0.0.1:8080/health（从源码部署时是 8000 端口），看返回的 schema 字段。ok 表示数据库已经可以注册；missing_users 或 missing_tenant_template 表示缺表或缺模板库，app 启动时会自动补建，可以重启 app 容器后再看。还不行就查看 app 和 postgres 容器的日志：数据库账号没有 CREATEDB 权限、数据库暂时连不上或正忙时，注册接口会返回 503 和具体原因。

打开网站提示 Invalid host header？

你用来访问的地址（比如局域网 IP 或另一个域名）不在允许列表里。把它加进服务器 .env 的 ALLOWED_HOSTS（逗号分隔）后重启 app 容器；用一键脚本部署的，也可以重新运行脚本并加上 --allowed-hosts。localhost、127.0.0.1 和 CORS_ORIGINS 里的主机默认就允许。

后端起不来，日志说缺环境变量？

检查 MAIN_DB_*、SECRET_KEY（≥ 16 字符）、CORS_ORIGINS 是否齐全。ENV=production 时还必须提供 CREDENTIAL_ENCRYPTION_KEY，否则应用会故意拒绝启动。

前端请求 /api 报跨域或 404？

开发模式下 Vite 把 /api 代理到 http://localhost:8000，先确认后端在 8000 端口活着。跨域错误通常是 CORS_ORIGINS 没把前端地址（如 http://localhost:3000）加进去，注意它是 JSON 数组格式。

课程任务的进度去哪里看？

界面上每个任务卡片都有实时进度；接口层面用 GET /course/status/{task_id} 轮询，GET /course/logs/{task_id} 看逐行日志。任务可随时 pause / resume / stop。

Swagger / 接口调试页面在哪里？

设置 DOCS_ENABLED=true 后访问 /docs（Swagger UI），原始 OpenAPI spec 在 /openapi.json。生产环境建议保持关闭。

我的平台账号密码安全吗？

第三方平台凭据在写入数据库前先用 Fernet 对称加密，密钥只放在服务器的环境变量里，不进仓库，也不打进镜像。每位用户的数据还存在各自独立的租户库里。

端口被占了怎么办？

一键脚本部署的对外端口默认是 8080，重新运行脚本时加 --port 换一个。从源码部署时改 .env 里的 APP_PORT（默认 8000），同时同步前端代理和 nginx 反代的上游端口。

怎么更新已部署的服务？

有新版本时，管理员登录后会看到提示，里面有版本号、更新说明和可以复制的更新命令，可以选「稍后提醒」（24 小时后再提示）或「跳过这个版本」。管理员是 ADMIN_EMAILS 里配置的邮箱，没配置时是第一个注册的账号。一键脚本部署的，进入安装目录运行 bash scripts/deploy_server.sh --tag <版本号> -y 就能更新，.env 和数据会保留。

从源码部署的整体升级：拉新代码后重新 docker compose -f docker-compose.server.yml up -d --build。单文件热修复：scripts/hotfix_publish.sh backend/app/main.py（需要配置 SERVER_IP 与 SSH key），后端文件会同步到远程仓库检出目录，再用 Compose 重建并替换 app 服务（--no-deps）；只读容器不会被直接写入，依赖层变更会触发整镜像重建。

桌面版「学道」怎么更新？

桌面版启动后会去 GitHub Releases 检查新版本。有新版本时会弹窗显示版本号和更新说明，点「现在更新」才会下载、安装并重启，正在运行的任务会中断；点「稍后」这次不更新，下次启动时再问。

安全与合规

安全基线

  • 后端容器非 root（UID/GID 10001）运行，只读根文件系统，Linux capabilities 全部裁剪。
  • nginx 强制 Content-Security-Policy、HSTS、frame-ancestors deny，登录接口限速 5 次/分。
  • Postgres 限制最大连接数、开启慢查询日志与 WAL 压缩；备份加密存储。
  • 安全漏洞请按 SECURITY.md 流程私下报告。
